# channel-github

Mentions of the bot in the conversation of a [GitHub](https://github.com) pull request as work items, replies in
that conversation, and approval cards that a person answers with a comment, behind the factory's channel port. It
runs on [Vercel Chat SDK](https://chat-sdk.dev) and keeps no state of its own. Decision:
[ADR 0059](../../../docs/decisions/0059-channel-port.md). The port's scenarios are in
[`ports/channel/features/`](../../../ports/channel/features/channel.feature).

## Quick start

```sh
export CHANNEL_TOKEN=... CHANNEL_SIGNING_SECRET=...   # CHANNEL_API_URL defaults to https://api.github.com
# A repository webhook sends issue_comment events with that secret; the receiver writes each delivery as
# {"headers": {...}, "body": "..."} to delivery.json.
npx @opensoftware/channel-github receive delivery.json
# {"kind":"work","workItem":{"id":"github:acme/web:12/4410","type":"task","title":"Fix the checkout button on Safari",...}}
npx @opensoftware/channel-github reply github:acme/web:12 "On it: run 7 started"
npx @opensoftware/channel-github ask github:acme/web:12 "Merge pull request 12 into main?"
# A person comments "/approve", received as a delivery:
npx @opensoftware/channel-github receive delivery.json
# {"kind":"decision","thread":"github:acme/web:12","card":"4412","choice":"approve","person":"github:varun"}
```

## How it behaves

- **The bot** is the user of `CHANNEL_TOKEN`, which `GET /user` names. A mention is `@<login>`. A token GitHub
  refuses exits 1 with `the channel refused the token`.
- **Deliveries** are `issue_comment` events of a repository webhook with JSON content. `receive` checks
  `X-Hub-Signature-256` (`sha256=` and the HMAC-SHA256 of the body with `CHANNEL_SIGNING_SECRET`); a refused delivery
  exits 1 and prints nothing.
- **Work items.** A person's comment that mentions the bot is a work item. Its title is the text's first line
  without the mention, its requester `github:<login>`, and its origin links to the comment. The bot's own comments
  and comments without a mention print nothing.
- **Approval cards.** GitHub has no buttons, so a card is a comment with the question, the line
  `Answer with /approve or /reject.` and the choices. A comment that is exactly `/<choice>` is a decision on the
  newest card of the bot in that conversation that offers the choice; a choice no card offers prints nothing.
  `receive` reads the conversation's last 100 comments to find the card.
- **Threads** are `github:<owner>/<repo>:<number>`, the conversation of a pull request. `reply` and `ask` comment
  there.

## Commands

| Command | What it does |
| --- | --- |
| `channel-github receive <delivery.json>` | Print the delivery's work item or decision, or nothing. |
| `channel-github reply <thread> <text>` | Comment the text; print `{"thread", "id"}`. |
| `channel-github ask <thread> <question> [--choice <name>]...` | Comment an approval card, by default with `approve` and `reject`; print `{"thread", "id"}`. |
| `channel-github messages <thread>` | Print the conversation's first 100 comments, oldest first, as `{"id", "thread", "author", "time", "text", "mine"}`. |

## Tests

The system tests run the port's `@conformance` scenarios against `fakes.github()`, the testkit's in-process fake of
GitHub's REST API (ADR 0058, ADR 0059). No real GitHub is called.

## Releases

release-please opens a release pull request from the Conventional Commits under `adapters/channel/github/`. Merging
it creates the tag `channel-github-v<version>`. The workflow `.github/workflows/publish-channel-github.yml` then
builds the package and publishes it to npm as `@opensoftware/channel-github`. The first release is `0.1.0`; until
`1.0.0`, a breaking change raises the minor version. The one-time setup is the same as for contracts
([`contracts/README.md`](../../../contracts/README.md#releases)). No credential is stored in the repository.
