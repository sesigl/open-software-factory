# channel-slack

Mentions of the bot in [Slack](https://slack.com) as work items, replies in their threads, and approval cards with
buttons, behind the factory's channel port. It runs on [Vercel Chat SDK](https://chat-sdk.dev) and keeps no state
of its own. Decision: [ADR 0059](../../../docs/decisions/0059-channel-port.md). The port's scenarios are in
[`ports/channel/features/`](../../../ports/channel/features/channel.feature).

## Quick start

```sh
export CHANNEL_TOKEN=xoxb-... CHANNEL_SIGNING_SECRET=...   # CHANNEL_API_URL defaults to https://slack.com/api/
# The receiver writes each request from Slack as {"headers": {...}, "body": "..."} to delivery.json.
npx @opensoftware/channel-slack receive delivery.json
# {"kind":"work","workItem":{"id":"slack:C0WEB:1767225600.000001/1767225600.000001","type":"task","title":"Fix the checkout button on Safari",...}}
npx @opensoftware/channel-slack reply slack:C0WEB:1767225600.000001 "On it: run 7 started"
npx @opensoftware/channel-slack ask slack:C0WEB:1767225600.000001 "Merge pull request 12 into main?"
# A press of "approve" on that card, received as a delivery:
npx @opensoftware/channel-slack receive delivery.json
# {"kind":"decision","thread":"slack:C0WEB:1767225600.000001","card":"1767225600.000003","choice":"approve","person":"slack:U0PERSON"}
```

## How it behaves

- **The Slack app** needs the Events API (`message.channels`, `app_mention`) and interactivity pointed at the
  receiver, and a bot token with `chat:write`, `users:read` and `channels:history`. The receiver answers Slack's
  `url_verification` and answers every request within 3 seconds; it then runs `receive` on the delivery.
- **Signatures.** `receive` checks `X-Slack-Signature` (`v0`, HMAC-SHA256 with `CHANNEL_SIGNING_SECRET`) and refuses
  a request that Slack signed more than 5 minutes from now, with the time from `OSF_NOW` or the clock. A refused
  delivery exits 1 and prints nothing.
- **Work items.** A person's message that mentions the bot (`<@bot>`) is a work item. Its title is the text's first
  line without the mention, its requester `slack:<user ID>` with the name `users.info` gives, and its origin links to
  the message with `chat.getPermalink`. The bot's own messages and messages without a mention print nothing.
- **Approval cards** are Block Kit messages with the question and one button per choice; a button's action ID is
  its choice. A press is a decision on that card. A text reply in the thread is not a decision.
- **Threads** are `slack:<channel>:<ts of the thread's first message>`. `reply` and `ask` post in that thread.
- **Channels** are `slack:<channel>`. `reply` and `ask` on a channel start a new thread; `messages` on a channel
  reads its newest 200 top-level messages (`conversations.history`), and on a thread all its messages, up to 1000.
  A message's `time` keeps Slack's microseconds.
- A token Slack refuses exits 1 with `the channel refused the token`.

## Commands

| Command | What it does |
| --- | --- |
| `channel-slack receive <delivery.json>` | Print the delivery's work item or decision, or nothing. |
| `channel-slack reply <thread> <text>` | Post the text in the thread; print `{"thread", "id"}`. |
| `channel-slack ask <thread> <question> [--choice <name>]...` | Post an approval card, by default with `approve` and `reject`; print `{"thread", "id"}`. |
| `channel-slack messages <thread or channel>` | Print each message, oldest first, as `{"id", "thread", "author", "time", "text", "mine"}`. |

## Tests

The system tests run the port's `@conformance` scenarios and this adapter's own scenarios in
[`features/`](features/slack.feature) against `fakes.slack()`, the testkit's in-process fake of Slack's Web API
(ADR 0048, ADR 0059). No real Slack is called.

## Releases

release-please opens a release pull request from the Conventional Commits under `adapters/channel/slack/`. Merging
it creates the tag `channel-slack-v<version>`. The workflow `.github/workflows/publish-channel-slack.yml` then builds
the package and publishes it to npm as `@opensoftware/channel-slack`. The first release is `0.1.0`; until `1.0.0`, a
breaking change raises the minor version. The one-time setup is the same as for contracts
([`contracts/README.md`](../../../contracts/README.md#releases)). No credential is stored in the repository.
