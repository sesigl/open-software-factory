# harness-acp

Runs any coding agent that speaks the Agent Client Protocol (ACP) behind the factory's harness port. The client
talks ACP to `harness-acp` as to the agent itself; the adapter adds a tool allowlist the agent cannot get around,
ends a cancelled turn within 5 seconds, exits with its agent, and exports each session as a run record. It runs the shared
[`harness-proxy`](../../../packages/harness-proxy/README.md). Decisions:
[ADR 0050](../../../docs/decisions/0050-harness-port.md), [ADR 0051](../../../docs/decisions/0051-harness-claude-code.md). The port's scenarios are in
[`ports/harness/features/`](../../../ports/harness/features/harness.feature).

## Quick start

Start an ACP agent from the ACP Registry behind the adapter, for example Claude Code through its ACP bridge. The
client may approve reads and edits; every other tool call is refused without asking it:

```sh
npx @opensoftware/harness-acp run --allow read,edit -- npx @agentclientprotocol/claude-agent-acp
```

The adapter now speaks ACP on stdin and stdout: `initialize`, `session/new`, `session/prompt`, `session/cancel`,
and from the agent `session/update` and `session/request_permission`. After the session, export it:

```sh
npx @opensoftware/harness-acp transcript <session ID>
```

It writes `$OUTPUT/run-record.json` and `$OUTPUT/transcript.jsonl`.

## How it behaves

- **Sessions and prompts** pass through unchanged. A prompt sent while a turn runs is a steering message and
  reaches the agent at once.
- **The agent works in its folder itself.** The adapter offers it no client file system and no terminal, whatever
  the client offers.
- **The allowlist.** With `--allow <kinds>`, a permission request for a tool call of an ACP tool kind outside the list
  (`read`, `edit`, `delete`, `move`, `search`, `execute`, `think`, `fetch`, `switch_mode`, `other`; a tool call without
  a kind is outside every list) gets the agent's reject option from the adapter, and the client is never asked. Without `--allow`, the
  client decides every tool call. The allowlist only sees tool calls the agent asks about.
- **Cancel.** `session/cancel` goes to the agent. When the turn has not ended 3 seconds later, the adapter stops the
  agent, ends the turn with `cancelled` and exits. The adapter always exits when its agent does,
  and stops the agent when the client hangs up.
- **The session record.** Every prompt, update, permission decision (`allowed`, `refused` or `refused by the allowlist`) and stop reason is one JSON line in `OSF_DATA/sessions/<session ID>.jsonl`, after a first line with the
  folder, the agent's name and version, and the resource attributes of the run.
- **The run record.** `transcript` writes a valid `run-record` (contracts): the resource of the session with
  `osf.harness.name` `acp` and `osf.harness.version` the agent's version, `gen_ai.conversation.id` the session ID,
  `osf.outcome` from the last stop reason (`end_turn` is `succeeded`, `cancelled` is `cancelled`, anything else is
  `failed`, and so is a session that is still in a turn), the tokens and the cost the agent reported, if any, in
  `gen_ai.usage.*` and `osf.cost.usd`, and `osf.transcript.uri` the `file:` URL of `transcript.jsonl`, a copy of the
  session record.

## Commands

| Command | What it does |
| --- | --- |
| `harness-acp run [--allow <kinds>] -- <agent command>...` | Start the agent and run the adapter on stdio until the agent exits. |
| `harness-acp transcript <session ID>` | Write the session's run record to `$OUTPUT/run-record.json` and its transcript to `$OUTPUT/transcript.jsonl`. |

## Releases

release-please opens a release pull request from the Conventional Commits under `adapters/harness/acp/`. Merging it
creates the tag `harness-acp-v<version>`. The workflow `.github/workflows/publish-harness-acp.yml` then builds the
package and publishes it to npm as `@opensoftware/harness-acp`. When the newest tag is missing on npm, the next run of
the workflow on `main` publishes it. To publish a tag again, run the workflow by hand with the tag. The first release
is `0.1.0`; until `1.0.0`, a breaking change raises the minor version.

The one-time setup is the same as for contracts ([`contracts/README.md`](../../../contracts/README.md#releases)): the
GitHub environment `npm`, a token only for the first version, then a trusted publisher for the workflow
`publish-harness-acp.yml`. No credential is stored in the repository.

## Scenarios

The adapter passes every `@conformance` scenario of the harness port (`testkit conformance ../../../ports/harness/features`)
and its own scenario in `features/`. The scripted harness for deterministic runs is this adapter with the testkit's
scripted agent: `harness-acp run -- <fakes.harness() command>` (ADR 0051).
