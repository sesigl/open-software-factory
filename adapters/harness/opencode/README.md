# harness-opencode

Runs opencode behind the factory's harness port. The client talks ACP to `harness-opencode` as to any agent; the
adapter starts opencode's own ACP server `opencode acp` behind the harness proxy. Every session asks before each edit
and command, a tool allowlist holds whatever the agent tries, a cancelled turn ends within 5 seconds, and each session
exports as a run record with the tokens opencode reported. Decision:
[ADR 0053](../../../docs/decisions/0053-harness-codex-opencode.md). The port's scenarios are in
[`ports/harness/features/`](../../../ports/harness/features/harness.feature).

## Quick start

Point opencode at a model gateway and let the client approve reads and edits; every other tool call is refused
without asking it:

```sh
OPENAI_BASE_URL=https://gateway.example.com/v1 OPENAI_API_KEY=<gateway key> OPENAI_MODEL=gpt-5.5 \
  npx @opensoftware/harness-opencode run --allow read,edit
```

The adapter now speaks ACP on stdin and stdout. After the session, export it:

```sh
npx @opensoftware/harness-opencode transcript <session ID>
```

It writes `$OUTPUT/run-record.json` and `$OUTPUT/transcript.jsonl`.

## How it behaves

- **The harness proxy** does what every harness adapter does: sessions and prompts pass through, a prompt sent while
  a turn runs reaches opencode within the turn, tool calls of kinds outside `--allow` are refused without asking the
  client, a cancelled turn that has not ended after 3 seconds is stopped, and each session is recorded
  ([`harness-proxy`](../../../packages/harness-proxy/README.md)).
- **opencode asks first.** The adapter's configuration lets reading, searching and the todo list run without asking,
  asks before every other tool, such as each edit (kind `edit`) and each command (kind `execute`), and denies web
  fetch and web search. `OPENCODE_DISABLE_PROJECT_CONFIG` keeps a folder's `opencode.json` from asking less.
- **Its own settings.** opencode keeps its settings, logins and sessions in `OSF_DATA/opencode`, never in the user's
  home. It reads no Claude Code settings or skills, loads no external plugins, and turns off auto update, the
  models.dev fetch, LSP downloads, sharing and the title call.
- **The model gateway.** One provider `osf` with `@ai-sdk/openai-compatible` calls the chat completions API at
  `OPENAI_BASE_URL` with `OPENAI_API_KEY` and the model `OPENAI_MODEL`. Without `OPENAI_MODEL`, `run` is a usage
  error.
- **The run record** has `osf.harness.name` `opencode`, `osf.harness.version` opencode's version and the tokens of all
  turns in `gen_ai.usage.*`. opencode reports no cost over ACP.
- **Platforms.** The adapter runs the binary of `opencode-<platform>-<arch>` that `opencode-ai` installs: Linux with
  glibc, macOS and Windows, on x64 and arm64.

## Commands

| Command | What it does |
| --- | --- |
| `harness-opencode run [--allow <kinds>]` | Start opencode and run the adapter on stdio until opencode exits. |
| `harness-opencode transcript <session ID>` | Write the session's run record to `$OUTPUT/run-record.json` and its transcript to `$OUTPUT/transcript.jsonl`. |

## Releases

release-please opens a release pull request from the Conventional Commits under `adapters/harness/opencode/`. Merging
it creates the tag `harness-opencode-v<version>`. The workflow `.github/workflows/publish-harness-opencode.yml` then
builds the package and publishes it to npm as `@opensoftware/harness-opencode`. The first release is `0.1.0`; until
`1.0.0`, a breaking change raises the minor version. The one-time setup is the same as for contracts
([`contracts/README.md`](../../../contracts/README.md#releases)). No credential is stored in the repository.

## Scenarios

The adapter passes every `@conformance` scenario of the harness port and its own scenarios in `features/`, against
the real opencode with the testkit's model gateway.
