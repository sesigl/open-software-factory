# harness-claude-code

Runs Claude Code behind the factory's harness port. The client talks ACP to `harness-claude-code` as to any agent;
the adapter starts Claude Code through its ACP bridge `@agentclientprotocol/claude-agent-acp` behind the harness
proxy. Every session asks before each edit and command, a tool allowlist holds whatever the agent tries, a cancelled
turn ends within 5 seconds, and each session exports as a run record with the tokens and the cost Claude Code
reported. Decision: [ADR 0052](../../../docs/decisions/0052-harness-claude-code.md). The port's scenarios are in
[`ports/harness/features/`](../../../ports/harness/features/harness.feature).

## Quick start

Point Claude Code at a model gateway and let the client approve reads and edits; every other tool call is refused
without asking it:

```sh
ANTHROPIC_BASE_URL=https://gateway.example.com ANTHROPIC_API_KEY=<gateway key> \
  npx @opensoftware/harness-claude-code run --allow read,edit
```

The adapter now speaks ACP on stdin and stdout. After the session, export it:

```sh
npx @opensoftware/harness-claude-code transcript <session ID>
```

It writes `$OUTPUT/run-record.json` and `$OUTPUT/transcript.jsonl`.

## How it behaves

- **The harness proxy** does what every harness adapter does: sessions and prompts pass through, a prompt sent while
  a turn runs reaches Claude Code within the turn, tool calls of kinds outside `--allow` are refused without asking
  the client, a cancelled turn that has not ended after 3 seconds is stopped, and each session is recorded
  ([`harness-proxy`](../../../packages/harness-proxy/README.md)).
- **Claude Code asks first.** Every session runs in Claude Code's permission mode `default`, which asks before each
  edit and each command. The adapter turns skipping permissions off for each session and passes no
  `session/set_mode`, and Claude Code ignores a folder's `defaultMode` that would ask less. Reads inside the folder
  and tools that the folder's `.claude/settings.json` allows run without asking, so the allowlist does not see them.
- **Its own settings.** Claude Code reads and keeps its user settings, logins and memory in `OSF_DATA/claude`, never
  in the user's home, and sends no traffic but its model calls.
- **The model gateway.** Claude Code calls `ANTHROPIC_BASE_URL` with `ANTHROPIC_API_KEY` and the model
  `ANTHROPIC_MODEL`.
- **The run record** has `osf.harness.name` `claude-code`, `osf.harness.version` the bridge's version, the tokens of
  all turns in `gen_ai.usage.*`, and Claude Code's cost of the session in `osf.cost.usd`.

## Commands

| Command | What it does |
| --- | --- |
| `harness-claude-code run [--allow <kinds>]` | Start Claude Code and run the adapter on stdio until Claude Code exits. |
| `harness-claude-code transcript <session ID>` | Write the session's run record to `$OUTPUT/run-record.json` and its transcript to `$OUTPUT/transcript.jsonl`. |

## Releases

release-please opens a release pull request from the Conventional Commits under `adapters/harness/claude-code/`.
Merging it creates the tag `harness-claude-code-v<version>`. The workflow
`.github/workflows/publish-harness-claude-code.yml` then builds the package and publishes it to npm as
`@opensoftware/harness-claude-code`. The first release is `0.1.0`; until `1.0.0`, a breaking change raises the minor
version. The one-time setup is the same as for contracts ([`contracts/README.md`](../../../contracts/README.md#releases)).
No credential is stored in the repository.

## Scenarios

The adapter passes every `@conformance` scenario of the harness port and its own scenarios in `features/`, against
the real Claude Code with the testkit's model gateway.
