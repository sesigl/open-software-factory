# channel-kit

What the channel adapters share: the channel port's `receive`, `reply` and `ask` commands around a chat's webhook
handler and its post call. A library: adapters depend on it, it has no command of its own and no state. Decisions:
[ADR 0039](../../docs/decisions/0039-libraries.md), [ADR 0059](../../docs/decisions/0059-channel-port.md).

## Quick start

The `cli.ts` of a channel adapter hands its channel to `runChannel`:

```ts
import { runChannel } from "@opensoftware/channel-kit";

process.exitCode = await runChannel({
  name: "channel-demo",
  thread: { form: "demo:<number>", pattern: /^demo:\d+$/ },
  api: "CHANNEL_API_URL is the demo chat's API.",
  async receive(keep) {
    // Register the chat's handlers; each gives its line to keep. Give the chat's webhook handler.
    return async (request, { waitUntil }) => {
      waitUntil(keep(request.text().then((said) => ({ said }))));
      return new Response("ok");
    };
  },
  async post(thread, post) {
    // Post the text, or an approval card with post.question and post.choices; give the message's ID.
    return "m-1";
  },
});
```

## API

| Export | What it does |
| --- | --- |
| `runChannel(channel, args?, io?)` | Runs `receive <delivery.json>`, `reply <thread> <text>` or `ask <thread> <question> [--choice <name>]...` with `runProgram` of `@opensoftware/cli` and returns the exit code. |
| `Channel` | `name`, `thread: { form, pattern }`, `api`, `receive(keep)` that gives a `Webhook`, and `post(thread, post)` that gives the posted message's ID. |
| `Webhook` | `(request, { waitUntil }) => Promise<Response>`, the shape of Vercel Chat SDK's `chat.webhooks.<adapter>`. |
| `Keep` | Takes a handler's promise of one line (a JSON object) or `undefined`. |
| `Post` | `{ text }` for `reply`, `{ question, choices }` for `ask`. |
| `Delivery` | `{ headers, body }`, the delivery file's form. |

- `receive` reads the delivery file, sends its headers and body as a `POST` request to the webhook, waits for every
  task the webhook passed to `waitUntil`, and prints each kept line. A webhook that answers 401 exits 1 with
  `the delivery's signature does not match CHANNEL_SIGNING_SECRET`; a handler's error exits 1 with its message,
  since a chat SDK only logs it. A file without `headers` and a `body` is a usage error (exit 2).
- `reply` and `ask` check the thread against `thread.pattern` (else a usage error that names `thread.form`), post,
  and print `{"thread", "id"}`. `ask` without `--choice` asks with `approve` and `reject`.

## Releases

release-please opens a release pull request from the Conventional Commits under `packages/channel-kit/`. Merging it
creates the tag `channel-kit-v<version>`. The workflow `.github/workflows/publish-channel-kit.yml` then builds
`dist/` with `pnpm build` and publishes the package to npm. The first release is `0.1.0`; until `1.0.0`, a breaking
change raises the minor version. An adapter that depends on the library names it with `workspace:*`; `pnpm pack`
writes the released version into the adapter's published `package.json`.

The one-time setup is the same as for contracts ([`contracts/README.md`](../../contracts/README.md#releases)). No
credential is stored in the repository.
