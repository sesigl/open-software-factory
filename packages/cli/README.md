# cli

What the command lines of the modules share: one way to run a command, print its lines and errors and choose
the exit code, a usage error that exits 2, and the input and output files of a command. A library: modules depend
on it, it has no command of its own and no state. Decisions: [ADR 0039](../../docs/decisions/0039-libraries.md),
[ADR 0040](../../docs/decisions/0040-cli-library.md).

## Quick start

The `cli.ts` of a module parses its arguments with `node:util` and hands the chosen command to `runProgram`:

```ts
import { parseArgs } from "node:util";
import { check, outputPath, readInputs, runProgram, writeText } from "@opensoftware/cli";

const { positionals, values } = parseArgs({ allowPositionals: true, options: { help: { type: "boolean" } } });
const [command, ...paths] = positionals;
const count = () => {
  check(paths.length, "name at least one runs file or folder"); // exits 2
  const inputs = readInputs(paths, /\.jsonl$/);
  writeText(outputPath("count.txt"), `${inputs.length}\n`);
  return { lines: [`counted ${inputs.length} files`] };
};
process.exitCode = await runProgram({
  name: "demo",
  usage: "Usage: demo count <file or folder>...\n",
  command: command === "count" ? count : undefined,
  help: values.help,
});
```

## API

| Export | What it does |
| --- | --- |
| `runProgram({ name, usage, command, help }, io?)` | Runs the command and returns the exit code. The command gives `{ lines, errors, exitCode }`: lines go to standard output, each error to standard error as `<name>: <error>`. The exit code is `exitCode`, else 1 with errors, else 0. A thrown `UsageError` exits 2, any other error 1, each printed as `<name>: <message>`. `help` prints the usage to standard output and exits 0; no command prints it to standard error and exits 2. |
| `UsageError`, `check(condition, message)` | A wrong option, argument or input. `check` throws a `UsageError` unless the condition holds. |
| `readInputs(paths, pattern)` | `{ file, text }` of each file named and of each file below each folder named whose path matches `pattern`, sorted by path. A missing path is a `UsageError`. |
| `writeText(path, text)` | Writes the file and creates its folder. |
| `outputPath(file, out?)` | `out` when the user gave `--out`, else `file` in `$OUTPUT`, else `file` in the current folder. |
| `packageVersion(url)` | The version in a `package.json`, for example `new URL("../package.json", import.meta.url)`. |

## Releases

release-please opens a release pull request from the Conventional Commits under `packages/cli/`. Merging it creates
the tag `cli-v<version>`. The workflow `.github/workflows/publish-cli.yml` then builds `dist/` with `pnpm build` and
publishes the package to npm. The first release is `0.1.0`; until `1.0.0`, a breaking change raises the minor
version. A module that depends on the library names it with `workspace:*`; `pnpm pack` writes the released
version into the module's published `package.json`.

The one-time setup is the same as for contracts ([`contracts/README.md`](../../contracts/README.md#releases)):
the GitHub environment `npm`, a token only for the first version, then a trusted publisher for the workflow
`publish-cli.yml`. No credential is stored in the repository.

## Configuration

| Variable | Meaning |
| --- | --- |
| `OUTPUT` | The folder `outputPath` puts files into. Unset: the current folder. |
