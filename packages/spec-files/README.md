# spec-files

Read the files that specify and prove a unit: the scenarios of Gherkin feature files and the test cases of JUnit
reports. spec-trace, proof and the repository checks read them with this library. A library: it has no command of
its own and no state. Decisions: [ADR 0039](../../docs/decisions/0039-libraries.md),
[ADR 0042](../../docs/decisions/0042-spec-files-library.md).

## Quick start

```ts
import { readFileSync } from "node:fs";
import { parseFeature, readJUnitFolder, scenarioIdOf, statusOf } from "@opensoftware/spec-files";

const { scenarios, errors } = parseFeature("a.feature", readFileSync("features/a.feature", "utf8"));
for (const scenario of scenarios) console.log(scenario.ids, statusOf(scenario), scenario.steps.length);

for (const test of readJUnitFolder("reports/junit") ?? []) {
  console.log(scenarioIdOf(test, /SCN-[A-Z][A-Z0-9]*-\d{3}/), test.status, test.seconds);
}
```

## API

| Export | What it does |
| --- | --- |
| `parseFeature(file, text)` | `{ scenarios, errors }`. Each scenario has `file`, `line`, `name`, `ids` and `statuses` (the values of its `@id=` and `@status=` tags), `tags` (feature, rule and scenario tags), `steps` (Background first; `And`, `But` and `*` take the keyword before them) and `examples` (rows of all Examples tables). A file that does not parse gives one error with its line. Uses the official Gherkin parser. |
| `statusOf(scenario)`, `tagValues(tags, key)` | The status of a scenario with exactly one `@status=` tag; the values of `@<key>=` tags. |
| `parseJUnit(xml)` | From the text or the bytes of a report, one test case per `<testcase>`, from `<testsuites>` or a lone `<testsuite>`: `name`, `classname`, `suite`, `properties`, `status` (`failure` and `error` are failed), `reruns` (`flakyFailure`, `flakyError`, `rerunFailure`, `rerunError`) and `seconds`. |
| `readJUnitFolder(dir)` | The test cases of every `.xml` file in the folder, by file name; `undefined` when there is none. |
| `scenarioIdOf(test, id)` | The property `scenario` of a test case, else the first match of `id` in its name, else in its class name. |

## Releases

release-please opens a release pull request from the Conventional Commits under `packages/spec-files/`. Merging it
creates the tag `spec-files-v<version>`. The workflow `.github/workflows/publish-spec-files.yml` then builds `dist/`
with `pnpm build` and publishes the package to npm. The first release is `0.1.0`; until `1.0.0`, a breaking change
raises the minor version. The one-time setup is the same as for contracts
([`contracts/README.md`](../../contracts/README.md#releases)).

## Configuration

This library reads no environment variables.
