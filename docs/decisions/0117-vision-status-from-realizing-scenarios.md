# 0117. The status of a vision scenario follows the scenarios that realize it

## Context

T-50. The 82 scenarios of `docs/vision/software-factory.feature` all said `@status=planned`, although module scenarios
with `@realizes=` implemented most of them. T-33 fixed the status lines once by hand; nothing kept them right. In the
same way, `TODO.md` had items that were open with every slice ticked (T-22, T-26, T-29).

## Decision

- **The rule.** A vision scenario says `@status=implemented` when at least one module scenario names it with
  `@realizes=` and every such scenario that is not `deprecated` is `implemented`. Otherwise it says `planned`. A vision
  scenario is never `deprecated` by this rule; one that goes away is deleted with its `@realizes=` tags.
- **The report.** `make docs` writes the table of the vision scenarios, each with its status and its realizing
  scenarios and theirs, under the marker `generated by make docs from software-factory.feature` in
  `docs/vision/README.md`. It reads the scenarios with `@opensoftware/spec-files`, the parser of spec-trace; the
  vision file holds several features, which Gherkin does not parse, so its tag lines are read line by line. DOCS-GEN
  fails when the table is stale, so a change of a realizing scenario's status shows in the vision's table.
- **The checks.** `osf check VISION` fails on each vision scenario whose status differs from the rule, with the status
  to set. `osf check TODO` fails on an open item of `TODO.md` that has ticked slices and no open one. An item without
  slices passes. Both are in the fast set of `make check-fast`.
- Changing a vision scenario's `@status` tag by this rule is no change of its text.

## Options considered

| Option | For | Against |
| --- | --- | --- |
| A rule in `osf check` and a generated table | Deterministic, fast, next to the other repository checks | spec-trace's own report does not list vision scenarios |
| A command of the module spec-trace | spec-trace owns scenario reports | The vision file is this repository's convention, not a general one; a new release of spec-trace for it |
| No status in the vision file, only the table | Nothing to keep in step | The vision file is read alone more often than the table |

## Prior art

No new module, dependency or service. Cucumber and spec-trace report scenario statuses per feature file; neither
rolls statuses up across `@realizes=` links, which are this repository's own convention (`docs/quality/checks.md`).

## Consequences

A pull request that implements the last realizing scenario of a vision scenario also sets its status and runs
`make docs`. A `@realizes=` tag that names no vision scenario is not checked yet: `SCN-FORE-001` names
`SCN-FACTORY-E2E-001`, which does not exist.
