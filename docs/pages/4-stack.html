Languages, storage, workflow engine, build and release tooling for the tool family, with the options weighed against each other and a recommendation for each. The deciding question throughout: what makes each tool easy to adopt alone and easy for outside contributors to work on.

Pros and cons for this project

LanguageForAgainst
TypeScript
  • Reference language of MCP and ACP; Vercel Chat SDK is TypeScript only
  • npx makes the “five-minute quick start” real
  • Temporal TypeScript SDK is official and actively developed
  • Strict mode with interfaces feels close to Java's ports and adapters
  • Runtime types need a validator (Zod or TypeBox)
  • Weaker for heavy concurrency and CPU work
  • Dependency trees are deep; supply-chain care needed
Python
  • Harbor, Inspect, LiteLLM and the judge and eval tooling are Python
  • uvx gives a one-line start
  • Natural for data work in scorekit and taskcapture
  • No Chat SDK equivalent for every platform
  • Typing is optional; needs pyright in CI to stay honest
  • Packaging for long-running services is weaker than the JVM's
Java
  • Your strongest language: fastest delivery and best judgment
  • Official MCP Java SDK, maintained with Spring AI
  • Temporal's Java SDK is its most proven; best OpenTelemetry auto-instrumentation
  • Excellent for robust services
  • Microsoft's Java bot SDK is retired, and the new Agents and Teams SDKs support only C#, JavaScript and Python
  • No Harbor, Chat SDK or LiteLLM equivalents
  • CLIs need a JVM or GraalVM native image
  • Few AI-tooling contributors expect Java
Go
  • Single static binaries; best for operators, proxies, collectors
  • Kubernetes ecosystem is Go
  • New language for you
  • Thinner agent-library ecosystem
Decision: TypeScript and Python, nothing else in the core. Two languages are the most a small project can maintain well. Java appears as a generated client from the OpenAPI contracts, so Java teams can integrate without the core being Java.

Which tool in which language

TypeScriptPython
factory-spec, proof, spec-trace, gatekeeper, intake (with Factory MCP), foreman, all harness, sandbox and channel adaptersrunlog, scorekit, taskcapture, observer, ledger CLI (its SQL is plain SQL)

02Storage

Every tool must work alone from files. Servers are added only in server mode, and the fewer stateful services an install needs, the more people will try it.

Operational database

OptionForAgainst
PostgreSQL
  • Temporal, Langfuse and the outbox all run on it
  • JSONB for event payloads; pgvector for agent memory
  • Every cloud offers it managed
  • A server to run, even for small installs
SQLite
  • Zero setup; perfect for CLI mode and tests
  • One writer; no shared server mode
MySQL
  • Temporal supports it
  • Langfuse and pgvector need Postgres; would mean two databases
Decision: PostgreSQL in server mode, SQLite in CLI mode, behind one query layer (Kysely or Drizzle in TypeScript, SQLAlchemy in Python). Agent memory starts as pgvector, not a separate vector database.

Analytics for ledger and traces

OptionForAgainst
DuckDB
  • Embedded; reads JSONL and Parquet directly
  • Postgres-like SQL
  • Single process; no shared dashboards
PostgreSQL views
  • Already there in server mode; Grafana reads it
  • Slows down past millions of spans
ClickHouse
  • Built for traces at scale; Langfuse stores its data there
  • Heavy for small installs; a different SQL dialect
Decision: ledger targets DuckDB and PostgreSQL first, which share nearly all SQL, and adds ClickHouse views when an install already runs ClickHouse for Langfuse.

Object storage for evidence, transcripts and benchmark artifacts

OptionForAgainst
Cloud S3, GCS, R2
  • No operations
  • Not self-hosted
SeaweedFS
  • Apache-2.0; closest replacement for MinIO; Kubernetes CSI driver
  • Smaller community than Ceph
Garage
  • Single binary; simple
  • AGPL-3.0; fewer S3 features
MinIO
  • Known by everyone
  • Community edition archived in April 2026; no new security fixes
Ceph (Rook)
  • Most mature at scale
  • Far too heavy for this
Decision: code against the S3 API only. SeaweedFS in the self-hosted distribution, cloud storage when managed, a local folder in CLI mode.

Event transport

OptionForAgainst
NATS JetStream
  • One small binary; durable streams; CloudEvents binding
  • One more service
Postgres outbox + polling
  • No new service; transactional with the state change
  • Fan-out to many consumers gets awkward
Kafka
  • Industry standard at scale
  • Heavy to operate for this volume
Webhooks only
  • Simplest
  • Retries and ordering are your problem
Decision: every tool writes events to a Postgres outbox in the same transaction as its state change; a relay publishes them to NATS JetStream. A small install can skip NATS and use webhooks from the outbox.

03Workflow engine for the foreman

OptionForAgainst
Temporal
  • Made for waits of days: signals, timers, child workflows
  • History UI shows every step of every work item
  • Workers in TypeScript, Python, Java or Go can share one workflow
  • MIT; runs on Postgres
  • A server cluster to operate
  • Deterministic-workflow rules take learning
DBOS
  • A library on top of Postgres: no extra service
  • Fits “useful alone” well
  • Younger; smaller operational track record for long human waits
Hatchet, Inngest, Restate
  • Good developer experience
  • Check each server's license before shipping it in an open-source distribution
LangGraph
  • Agent graphs with checkpoints
  • Orchestrates model calls, not a delivery process with people and CI
Decision: Temporal. Keep the foreman's stage logic in plain functions so a DBOS backend stays possible for the single-VM profile. This is the one place where Java would also be a good fit, through Temporal's Java SDK, if you want to own the foreman yourself.

04Repository, build and release

OptionForAgainst
pnpm + uv + Nx
  • Native package managers per language; contributors know them
  • Nx builds and tests only what a change affects, with caching
  • Large community
  • Nx is TypeScript-first; its Python support comes from a community plugin
  • Another config layer
pnpm + uv + moon
  • Polyglot by design; pins Node and Python versions; simple config
  • Smaller community
Bazel
  • Hermetic and polyglot; scales to anything
  • Steep; JavaScript and Python rules fight the native tools; scares contributors
Gradle
  • You know it well
  • Unexpected for TypeScript and Python contributors; Node and Python plugins are awkward
Make or just only
  • Zero learning; this repository already uses make
  • No affected-only builds or caching; CI slows down as adapters grow
Decision: a monorepo with pnpm and uv workspaces and a top-level make for familiar commands. Add Nx for the task graph and caching when CI passes about ten minutes. Release each package independently with release-please, which handles npm and PyPI packages from conventional commits, rather than Changesets, which is JavaScript only.

05Contracts and code generation

OptionForAgainst
TypeSpec
  • One compact source that emits OpenAPI 3.1 and JSON Schema
  • Reads like Java interfaces
  • Another language to learn, though a small one
Hand-written JSON Schema and OpenAPI
  • No extra tool
  • Verbose; the two drift apart
Protobuf with buf
  • Best breaking-change checks and code generation
  • MCP, CloudEvents and REST here are JSON; it would be a translation layer
Decision: TypeSpec for formats and APIs, AsyncAPI for events. Generate TypeScript types with openapi-typescript, Python models with datamodel-code-generator (Pydantic), and Java clients with openapi-generator. Block breaking changes in CI with oasdiff.

08Risks and when to revisit

  • You would work mostly outside Java.Mitigation: write TypeScript in a Java-like style (strict types, interfaces for ports, constructor injection), and take the foreman in Java on Temporal if that becomes the bottleneck. Its workflow contract stays language-neutral.
  • Langfuse makes the full profile heavy.Revisit if users complain about install size; Phoenix is the fallback, and runlog speaks OTLP to both.
  • Nx's Python support is a community plugin.If it breaks, switch the task graph to moon; the packages themselves use only pnpm and uv, so nothing else moves.
  • Fast-moving dependencies.ACP, the OpenTelemetry GenAI conventions and the MCP Registry API are all still changing. Pin versions and keep each behind one adapter.
