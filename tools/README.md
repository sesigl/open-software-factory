# tools

The repository tooling: the deterministic checks from [`docs/quality/checks.md`](../docs/quality/checks.md) and
the helpers behind `make`. From phase 2 on, the released `spec-trace` module replaces TRACE, STEPS and PASS.

## Quick start

```sh
make install     # pnpm, uv and the pinned lychee and oasdiff binaries
make check       # lint and the static checks, in seconds
make verify      # everything: lint, types, all system tests, all checks
```

## Commands

`make` calls `osf`; run it directly with `node tools/bin/osf.ts <command>` from the repository root.

| Command | Make target | What it does |
| --- | --- | --- |
| `osf check [ID ...]` | `make check` | Run the named checks. No ID runs the fast set: SPEC, TRACE, STEPS, NOSKIP, ASSERT, BOUNDARY-STATIC, BOUNDARY-ENV, ISOLATION, DOCS-GEN, DOCS-LINKS, ADR. |
| `osf check --all` | `make verify` | Also PASS, FLAKE, BUDGET (they read `reports/junit/`), SPECGUARD, DOCS-AFFECTED and CONTRACT (they compare with `OSF_BASE`). |
| `osf docs-affected` | `make docs-affected` | List hand-written docs whose `covers:` paths changed since `OSF_BASE`. |
| `osf docs` | `make docs` | Regenerate every README section below a `generated by make docs` marker. |
| `osf new-module <name>` | `make new-module NAME=x` | Copy `modules/_template` and register the scenario prefix. |
| `osf next-id <module>` | `make next-id MODULE=x` | Print the next free scenario ID. |
| `osf agents-sync` | `make agents-sync` | Link `skills/` into `.claude/skills/`, `.agents/skills/` and `.opencode/skills/`. |

Each failure prints one line: the check ID, `file:line`, and what to fix. Each check ends with `ID ok` or
`ID failed: N`. The exit code is 1 when any check failed.

## Configuration

| Variable | Meaning |
| --- | --- |
| `OSF_BASE` | Git ref to compare with for SPECGUARD, DOCS-AFFECTED, CONTRACT and the dependency rule of ADR. `make` uses the merge base with `origin/main`. Without it, these comparisons pass with a note. |
| `OSF_APPROVALS` | JSON file with the pull request reviews (GitHub's reviews format). SPECGUARD accepts a change when a code owner of the file approved. |
| `OSF_PR_BODY` | File with the pull request description. DOCS-AFFECTED accepts `docs-reviewed: <path>` lines in it. |
| `OSF_JUNIT_DIR` | Folder with JUnit XML results. Default `reports/junit`. |
